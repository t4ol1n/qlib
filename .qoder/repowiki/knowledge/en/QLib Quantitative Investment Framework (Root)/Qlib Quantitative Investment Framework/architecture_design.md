The `qlib/` package is organized as layered sub-packages that compose the end-to-end quant pipeline: `core_runtime` (config/log/constants) initializes global state first; `data/` provides dataset, storage, and provider abstractions consumed by every upper layer; `model/` defines base model/trainer interfaces plus built-in models, while `contrib/model/` holds user-contributed PyTorch/XGBoost/CatBoost implementations that plug into the same interface; `strategy/` and `contrib/strategy/` supply rule- and signal-based strategies that consume model outputs; `backtest/` orchestrates execution of strategies against historical data via an exchange/executor loop; `workflow/` (plus `cli/`) composes tasks, experiments, and online pipelines that orchestrate data → model → strategy → backtest; `rl/` adds a reinforcement-learning branch with its own simulator, trainer, and order-execution modules that reuse `data/` and `workflow/`; `utils/` offers shared helpers (parsing, serialization, parallelism, time) used across all children. Cross-child communication is contract-driven: each layer exposes a small set of base classes/interfaces in its `__init__.py` or `base.py`, and child packages import only those contracts rather than reaching into sibling internals.
