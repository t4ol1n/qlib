The module is organized as a flat collection of self-contained example projects under `examples/`, each targeting a different usage pattern of the Qlib library:
- `benchmarks/<Model>/` — one subdirectory per alpha model (LightGBM, XGBoost, CatBoost, MLP, LSTM, GRU, Transformer, TFT, TRA, GATs, etc.). Each contains a `README.md`, `requirements.txt`, and one or more `workflow_config_<model>_<dataset>.yaml` files consumed by `qrun`. Models are not implemented here; they reference Qlib-contrib models via YAML configuration.
- `benchmarks_dynamic/` — dynamic/rolling benchmark scripts (`DDG-DA`, baseline rolling workflows).
- Top-level entry points: `workflow_by_code.py` and `workflow_by_code.ipynb` show programmatic workflow construction using `qlib.workflow.R`, `SignalRecord`, `PortAnaRecord`, `SigAnaRecord`; `run_all_model.py` provides a Fire-based CLI that auto-discovers `benchmarks/*/` folders, creates isolated conda environments per model, installs dependencies from each folder's `requirements.txt`, runs `qrun` against matching `workflow_config_*.yaml` files, and aggregates metrics via MLflow experiment records into markdown tables.
- Specialized workflow examples live in sibling directories: `highfreq/` (1-min data with custom ops/handlers), `nested_decision_execution/`, `online_srv/`, `orderbook_data/`, `portfolio/`, `rl_order_execution/`, `hyperparameter/LightGBM/`, `model_interpreter/`, `model_rolling/`, `rolling_process_data/`, `data_demo/`, `tutorial/`, `rl/`.
- Dependency direction is strictly outward: examples import from `qlib` (workflow, data, strategy, contrib) but contain no shared internal package — each example is independently runnable via `python <script>` or `qrun <config.yaml>`.
