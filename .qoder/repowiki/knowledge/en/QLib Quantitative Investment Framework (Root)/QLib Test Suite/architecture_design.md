Tests are organized by feature area under `tests/` mirroring the QLib package structure: `backtest/` for strategy tests, `data_mid_layer_tests/` for handler/dataset/processor layers, `dataset_tests/`, `rl/` for reinforcement learning components, `rolling_tests/`, `storage_tests/`, `ops/`, `model/`, and `misc/`. Root-level files (`test_all_pipeline.py`, `test_workflow.py`, `test_contrib_model.py`, etc.) exercise full workflows via configuration-driven instantiation using `qlib.tests.config` fixtures like `CSI300_GBDT_TASK`. A shared `conftest.py` conditionally ignores the `rl/` subpackage on non-Linux platforms. `pytest.ini` registers a `slow` marker and suppresses known deprecation/user warnings. Tests rely on `qlib.workflow.R` (MLflow-backed experiment recorder) to run train/predict/backtest pipelines and clean up temporary MLruns directories in `tearDownClass`.
