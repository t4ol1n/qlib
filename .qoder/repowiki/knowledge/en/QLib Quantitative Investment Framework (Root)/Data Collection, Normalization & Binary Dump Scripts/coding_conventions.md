- Each data source lives in its own directory under `data_collector/` containing a `collector.py` that subclasses `BaseCollector`/`BaseNormalize` and a `Run(BaseRun)` whose `collector_class_name`/`normalize_class_name` properties resolve the concrete class by region+interval suffix.
- Collectors implement the three abstract methods `get_instrument_list`, `normalize_symbol`, and `get_data(symbol, interval, start, end)` returning a DataFrame with `symbol` and `date` columns, then rely on `BaseCollector._simple_collector` to handle retries, length checks, and CSV persistence.
- Normalization classes subclass `BaseNormalize` and implement `normalize(df)` plus `_get_calendar_list()`, with region-specific variants (e.g. `YahooNormalizeCN1d`, `YahooNormalizeUS1min`) composed via multiple inheritance over a calendar mixin and a frequency mixin.
- CLI entry points are exposed through `fire.Fire(...)` at the bottom of each script, mapping string commands to classes or functions (e.g. `dump_all`, `dump_fix`, `dump_update`, `DataHealthChecker`).
- Concurrent processing is uniformly done with `ProcessPoolExecutor` or `joblib.Parallel` over file lists, wrapped in `tqdm` progress bars, and logged via `loguru.logger` rather than print statements.
- Symbol/file naming is canonicalized through `qlib.utils.code_to_fname` / `fname_to_code` so instrument directories under `features/` stay lowercase and stable across platforms.
