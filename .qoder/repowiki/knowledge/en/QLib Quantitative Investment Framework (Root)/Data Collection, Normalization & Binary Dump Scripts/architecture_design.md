The module is organized around two parallel pipelines. The `data_collector/` subpackage implements a pluggable collector framework defined in `base.py`: `BaseCollector` (abstracts instrument enumeration, symbol normalization, concurrent fetching via `joblib.Parallel`, retry/backoff, and per-symbol CSV output), `BaseNormalize` / `Normalize` (processes raw CSVs with a pluggable normalizer class using `ProcessPoolExecutor`), and `BaseRun` (dynamic `importlib`-based loader of region-specific `collector.py` classes). Concrete collectors live in sibling directories (`yahoo`, `cn_index`, `us_index`, `br_index`, `crypto`, `fund`, `pit`, `baostock_5min`, plus `contrib/` helpers); each provides a `collector.py` with a subclass of `BaseCollector`/`BaseNormalize` and a `Run(BaseRun)` exposing CLI commands. Top-level scripts provide the end-to-end entry points: `get_data.py` wraps `qlib.tests.data.GetData` via `fire` for one-click dataset downloads; `dump_bin.py` defines `DumpDataBase` and subclasses `DumpDataAll` / `DumpDataFix` / `DumpDataUpdate` to convert normalized CSVs into Qlib's `.bin` feature files, `calendars/<freq>.txt`, and `instruments/all.txt`; `dump_pit.py` writes point-in-time financial statements into a custom binary layout under `financial/<symbol>/<field>_<interval>.{data,index}`; `check_data_health.py` validates completeness of both CSV source and dumped Qlib datasets. Dependency direction flows outward: concrete collectors depend on `base.py` and shared `utils.py`, while top-level dump/check scripts depend only on `qlib.utils` and `qlib.data` — no cross-import between collectors.
